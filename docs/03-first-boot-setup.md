# 3. Первая настройка платы

У платы всего 64 МБ ОЗУ, а YOLOv8 + камера + NPU-рантайм эту память съедают почти целиком. Без пары настроек модель просто не загрузится («Can't allocate memory»). Делаем всё через `adb shell`.

## 3.1. Добавляем swap (подкачку)

Свободное место на SD-карте можно использовать как виртуальную память. Раздел под swap должен уже существовать в образе (в стандартной прошивке Luckfox это `/dev/mmcblk1p8`, но проверьте у себя через `lsblk` или `fdisk -l`, если карта другого объёма — раздел может называться иначе).

```bash
adb shell

mkfs.ext4 /dev/mmcblk1p8      # на все вопросы просто жмите Enter
mkswap /dev/mmcblk1p8
swapon /dev/mmcblk1p8
free -m                        # убедитесь, что строка Swap не нулевая
```

Swap отключается при каждой перезагрузке, поэтому автоматизируем включение через `init.d` (эта система инициализации используется в стандартном образе Buildroot):

```bash
cd /etc/init.d
cat > S90autoswap << 'EOF'
#!/bin/sh
case $1 in
    start)
        swapon /dev/mmcblk1p8
        ;;
    stop)
        ;;
    *)
        exit 1
        ;;
esac
EOF
chmod +x S90autoswap
```

Перезагрузите плату (`reboot`) и снова проверьте `free -m` — swap должен подключиться сам.

## 3.2. Отключаем лишние автозапускаемые службы

В стандартном образе по умолчанию поднимаются сервисы, которые не нужны для детекции и просто отъедают память:

| Скрипт в `/etc/init.d` | Что делает | Нужен ли |
|---|---|---|
| `S49ntp` | синхронизация времени по сети | нет, если не нужны сетевые запросы с точным временем |
| `S50sshd` | SSH-сервер | нет, если пользуетесь ADB |
| `S50telnet` | Telnet-сервер | нет, аналогично |
| `S91smb` | сетевые папки (Samba) | нет, если не нужен доступ к файлам по сети |
| `S99python` | автозапуск `boot.py`/`main.py` из `/root`, если они есть | нет, у нас таких файлов не будет |

Проще всего перенести их в отдельную папку, чтобы не запускались, но не удалять (можно будет вернуть):

```bash
mkdir -p /oem/services_backup
mv /etc/init.d/S49ntp /etc/init.d/S50sshd /etc/init.d/S50telnet /etc/init.d/S91smb /etc/init.d/S99python /oem/services_backup/ 2>/dev/null
reboot
```

## 3.3. killall rkipc перед своими программами

Служба `rkipc` (штатное видеонаблюдение платы) держит камеру занятой. Перед запуском любой своей программы, использующей камеру, всегда выполняйте:

```bash
killall rkipc
```

Это стоит держать в голове на постоянку — большинство ошибок вида «камера не открылась» или «не хватает памяти» лечатся именно этой командой.

## 3.4. Проверяем камеру

Определяем, к какому `/dev/videoN` подключилась CSI-камера:

```bash
v4l2-ctl --list-devices
```

В блоке `rkisp_mainpath (platform:rkisp-vir0)` будет путь вида `/dev/video11` — обычно именно это устройство и нужно (первое в списке этого блока). Запомните номер — он используется в коде (`CAMERA_DEV`) в [cpp/HelloDetector/src/main.cc](../cpp/HelloDetector/src/main.cc).

Если хотите на этом шаге просто убедиться, что камера физически работает и передаёт картинку, можно собрать минимальный пример с OpenCV Mobile (see статью на Хабре, раздел «CSI камера») — но для целей этой инструкции достаточно перейти сразу к сбору датасета, программа для этого уже сама открывает камеру и сохраняет кадры.
