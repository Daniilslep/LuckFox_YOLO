# 5. Обучение модели в Google Colab

Обучение самой нейросети и её конвертация в формат RKNN требуют Linux и специфичных версий библиотек. Чтобы не воевать с этим на своём компьютере, используем **Google Colab** — там уже есть Linux, Python и бесплатный GPU. Подходит для Windows, macOS и Linux одинаково — всё происходит в браузере.

## 5.1. Что такое Google Colab и как туда попасть

1. Откройте https://colab.research.google.com/ и войдите с Google-аккаунтом (можно создать бесплатно).
2. `Файл → Загрузить блокнот` → выберите файл [`colab/01_train_and_export.ipynb`](../colab/01_train_and_export.ipynb) из этого репозитория (либо просто загрузите его через drag-n-drop).
3. Включите GPU: `Среда выполнения → Сменить среду выполнения → Аппаратный ускоритель → GPU (T4)`.

Ноутбук выполняется по ячейкам сверху вниз — нажимайте `Shift+Enter` на каждой ячейке по очереди и ждите, пока она отработает (слева появится галочка), перед тем как переходить к следующей.

## 5.2. Что делает ноутбук, по шагам

1. **Установка зависимостей** — `pip install ultralytics`.
2. **Загрузка датасета** — либо через подключение Google Диска (`drive.mount`), либо прямой загрузкой zip-архива в сессию Colab. Датасет — тот, что вы подготовили на шаге [04-dataset.md](04-dataset.md).
3. **Обучение** — `YOLO('yolov8n.pt').train(...)`. По умолчанию 100 эпох на изображениях 640×640 — обычно достаточно, но если объект простой и датасет небольшой, модель может сойтись быстрее (тогда сработает `patience`/early stop сам).
4. **Проверка качества** — считает mAP50 / mAP50-95 на валидационной части.
5. **Бэкап весов на Google Диск** — на случай, если сессия Colab отключится.
6. **Экспорт в ONNX** — не обычным экспортом Ultralytics, а специальным форком [airockchip/ultralytics_yolov8](https://github.com/airockchip/ultralytics_yolov8), который убирает из графа модели постобработку (NMS) и DFL-блок — эти операции NPU считать не умеет, их придётся вычислять уже на плате (это уже сделано в коде `HelloDetector`, см. [06-build-and-deploy.md](06-build-and-deploy.md)).
7. **Квантизация и конвертация в RKNN** — через [rknn-toolkit2](https://github.com/airockchip/rknn-toolkit2) и примеры из [rknn_model_zoo](https://github.com/airockchip/rknn_model_zoo). NPU процессора RV1103 считает только в int8, поэтому модель обязательно квантизируется — для этого нужна «калибровка» на части ваших изображений (обычно достаточно 20-50 штук, можно больше — точнее, но дольше).
8. **labels.txt** — текстовый файл с именами классов, по одному в строке, в том же порядке, что в `data.yaml`. Обязательно скачайте — он нужен на следующем шаге.

## 5.3. Что должно получиться на выходе

Два файла, которые нужно скачать себе на компьютер:

- `yolov8.rknn` (или `my_model.rknn`) — сама модель для NPU.
- `labels.txt` — список классов.

Если что-то из шагов конвертации падает с ошибкой — почти всегда причина одна из:

- неправильный/относительный путь к файлу весов или датасету (Colab требует абсолютные пути вида `/content/...`);
- забыли поменять `model:`/`imgsz:` в `default.yaml` форка перед экспортом в ONNX;
- в списке калибровки (`data_subset.txt`) — не найдены файлы (проверьте, что путь к папке с изображениями существует).

Дальше — [06-build-and-deploy.md](06-build-and-deploy.md): собираем программу для платы и запускаем детекцию.
