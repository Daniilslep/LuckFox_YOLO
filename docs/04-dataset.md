# 4. Датасет: снимаем и размечаем свой объект

Модель должна увидеть ваш объект во многих условиях: разные ракурсы, расстояния, освещение, фон. Чем разнообразнее датасет — тем лучше итоговая детекция.

Ориентир по количеству: **50-150 фотографий** объекта для одного класса вполне достаточно для хобби-проекта (у автора оригинальной статьи на 2 класса получилось mAP50 ≈ 0.95-0.98 при таком объёме, при некотором качестве разметки).

## 4.1. Снимаем датасет камерой платы

Лучше снимать именно той камерой, которая потом будет работать в проекте — так модели проще, изображение не будет отличаться по цвету/шумам/искажениям от того, что она увидит в реальной работе.

В этом репозитории есть готовая программа [tools/dataset_capture](../tools/dataset_capture) — она открывает камеру платы и по нажатию Enter в консоли сохраняет очередной кадр в папку с именем класса.

### Собираем dataset_capture

Программа собирается тем же кросс-компилятором, что и всё остальное на плате. Если у вас нет Linux — используйте Google Colab (см. [05-training-colab.md](05-training-colab.md), там же описано, как подключить кросс-компилятор — то же самое подойдёт и здесь):

```bash
# внутри Colab или Linux/WSL
git clone --depth 1 https://github.com/LuckfoxTECH/luckfox-pico/
export GCC_COMPILER=$(pwd)/luckfox-pico/tools/linux/toolchain/arm-rockchip830-linux-uclibcgnueabihf/bin/arm-rockchip830-linux-uclibcgnueabihf

cd tools/dataset_capture/libs
bash download.sh          # скачает OpenCV Mobile 4.10 под Luckfox
cd ..
mkdir build && cd build
cmake ..
make
```

Получите бинарник `dataset_capture` в папке `build`.

### Заливаем на плату и снимаем

```bash
adb push dataset_capture /root/dataset_capture
adb shell chmod +x /root/dataset_capture
adb shell

cd /root
killall rkipc            # обязательно перед запуском своих программ с камерой
./dataset_capture
```

Программа спросит имя класса — введите его латиницей без пробелов (например `cup`, `screwdriver`, `mypart`). Дальше нажимайте **Enter** для каждого снимка — покрутите объект перед камерой, меняйте расстояние, ракурс, фон, освещение. Когда наснимали достаточно — введите `q` и Enter.

Кадры лежат в `/root/<имя_класса>/`. Скачайте их на компьютер:

```bash
exit   # выходим из adb shell
adb pull /root/<имя_класса> ./raw_dataset
```

## 4.2. Размечаем датасет

Модели нужна не просто картинка, а рамка (bounding box) вокруг объекта на каждом фото плюс имя класса. Есть три варианта, выбирайте любой:

### Вариант A — Roboflow (рекомендуется, если есть интернет)

[Roboflow](https://roboflow.com/) — бесплатный (в разумных пределах) веб-сервис для разметки и экспорта датасетов прямо в формат YOLOv8.

1. Зарегистрируйтесь на roboflow.com, создайте новый проект типа **Object Detection**.
2. Загрузите все фотографии из `raw_dataset`.
3. Разметьте рамки вручную, либо попробуйте инструмент **Smart Polygon** — он в полуавтоматическом режиме предлагает контур объекта по клику, это заметно быстрее ручной обрисовки (качество зависит от освещения и контраста объекта с фоном).
4. При желании добавьте аугментацию (Generate → Augmentation): повороты, изменение яркости/насыщенности, размытие — это увеличивает количество обучающих изображений без новой съёмки.
5. Экспортируйте датасет в формате **YOLOv8** (Export → format `YOLOv8`) — получите zip-архив с папками `train/valid/test`, файлами `images/`, `labels/` и `data.yaml`.

### Вариант B — офлайн-разметчик из этого репозитория (без интернета и регистраций)

Если фотографий не очень много и на кадре только один объект — можно разметить всё прямо в браузере, без загрузки данных куда-либо.

1. Откройте файл [tools/labeler/labeler.html](../tools/labeler/labeler.html) прямо в браузере (двойной клик).
2. Впишите имя класса в поле сверху.
3. Нажмите «Выбрать папку с фото» и укажите `raw_dataset`.
4. На каждом фото обведите объект рамкой левой кнопкой мыши.
   - `Enter` / `N` — сохранить рамку и перейти к следующему фото
   - `S` — пропустить кадр (объекта не видно / кадр плохой)
   - `X` — сбросить текущую рамку
   - `B` — вернуться к предыдущему фото
5. В конце нажмите «Скачать labels.zip» — в архиве будут `.txt`-файлы в формате YOLO (по одному на каждое размеченное фото) и `README.txt` с подсказкой.

> Ограничение этого инструмента: одна рамка на фото и один класс на весь проход. Если у вас несколько классов объектов — размечайте датасет по одному классу за проход (меняя имя класса в поле сверху и складывая результат в разные подпапки), либо используйте Roboflow/CVAT для полноценной многоклассовой разметки.

### Вариант C — другие инструменты

- **[CVAT](https://www.cvat.ai/)** — мощный бесплатный опен-сорсный инструмент (облачная версия или разворачивается локально в Docker), поддерживает команды, множество классов, разные типы разметки.
- **[makesense.ai](https://www.makesense.ai/)** — простой браузерный инструмент без регистрации, похож на вариант B, но с поддержкой нескольких классов.
- **[LabelImg](https://github.com/HumanSignal/labelImg)** — классический десктопный инструмент разметки (Windows/Linux/macOS), работает офлайн.

## 4.3. Собираем структуру датасета

Для обучения YOLOv8 нужна такая структура папок:

```text
my_dataset/
├── data.yaml
├── train/
│   ├── images/    *.jpg
│   └── labels/    *.txt  (тот же имя, что и у картинки)
└── valid/
    ├── images/
    └── labels/
```

Каждый `.txt`-файл содержит по одной строке на объект в формате:

```text
<class_id> <x_center> <y_center> <width> <height>
```

где все координаты — относительные (0..1) от размера изображения, а `class_id` — номер класса, начиная с 0 (порядок соответствует списку `names` в `data.yaml`).

Пример `data.yaml` для одного класса:

```yaml
train: /content/my_dataset/train/images
val: /content/my_dataset/valid/images
test: /content/my_dataset/test/images   # можно не создавать, если нет тестовой части

nc: 1
names: ['my_object']
```

Возьмите **80-90%** размеченных фото в `train`, остальное — в `valid` (простое случайное разбиение, вручную или маленьким скриптом).

Если вы использовали Roboflow — всё это Roboflow сделает сам при экспорте, останется только заархивировать и загрузить результат в Colab. Если размечали офлайн-разметчиком — разложите фото и `.txt`-файлы по папкам вручную (или простым скриптом на Python) и напишите свой `data.yaml` по примеру выше.

Готовый датасет упакуйте в `.zip` — он понадобится на следующем шаге, в Google Colab: [05-training-colab.md](05-training-colab.md).
